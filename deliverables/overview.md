## 四、修掉的两个真实缺陷（实测发现，非推测）

1. **390px 下整页横向溢出 592px**。
   根因不是表格本身，而是 `1fr` 网格轨道的隐式 `min-width:auto` 被内容
   （`table.data{min-width:520px}`）顶住不放，轨道被撑到 572px。
   修法：给 `.demo-grid > *` 与 `.result-area` 置 `min-width:0`，
   让滚动条正确落到 `.tbl-wrap` 上。
2. **技术页动画利用率过低**（8 张图只有 1 类动画）。
   附带踩坑：`.route-ok` 与 `.flow-dash` 都用 `animation` 简写，叠加时后者整体胜出、
   虚线流动会丢，必须组合声明 `animation: dashmove ..., routeOk ...;`。

## 六、主页排版修复（第 4 轮）—— 一处 CSS 缺陷排坏整块内容

用户反馈"index 页面上有些排版问题"。量化后定位到**一个根因**，而非多处零散问题。

### 6.1 根因：`.cap-points li` 用 grid 做两列，被内联节点打散

`li` 的内容是「文本 + `<b>` + 文本」这种**混合内联节点**。`display:grid` 会把每一段连续文本、
每一个 `<b>/<code>` 各当作**独立网格项**自动排布 —— `<b>` 于是被塞进 20px 宽的圆点列里，
竖着排成一条窄条。

实测证据：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `li#0` 盒高 | **233.8 px** | **50.8 px** |
| `<B>来源（页码 + 行坐标）` 盒子尺寸 | **w=20 × h=197**（6 个字竖排） | 正常成行 |
| 能力区两列高比 | **2.27 : 1** | **1.07 : 1** |
| `#capabilities` 章节总高 | **3920 px** | **2263 px** |
| 整页高度 | **7291 px** | **5633 px** |

修法：改 `display:block` + `padding-left` + **绝对定位**圆点。内联节点恢复正常成行。

> 判别技巧：把 `li` 临时改成 `display:block` 对比高度差 —— 若差值 >100px，基本可断定
> 内联节点被网格项化了，而不是文字真的那么多。

### 6.2 其余 3 处（同一轮内一并修掉）

1. **chip 文案裁剪正则漏了"利润表"**：`/(资产|利润)负债?表?/` 匹配不到"利润表"，
   导致第二条 chip 显示成整句、其余显示短科目名，**视觉不一致**。
   → 补全为 `/(资产负债表|利润表|现金流量表)/`。
2. **窄面板里表格被挤成竖条**：勾稽结果区面板只有 380px，`table.data` 的"值"列
   吃掉 205px，把"科目"列压到 73px → 副标题「报表行名 资产总计」折成 **25px 宽的竖条**，
   单行撑到 204px / 394px。
   → 数值列 `white-space:nowrap`、科目列 `min-width:132px`、副标题不换行、
   `.tbl-wrap` 始终允许横向滚动（原来只在 ≤768px 开，桌面端窄面板漏了）。
   修复后行高统一 **71px**、结果区总高 1036 → **447px**。
3. **示意图在窄容器里被压到读不出**：`svg` 是 `width:100%` 等比缩放，
   1024px 笔电下两列窄格只有 435px，480 宽的图压到 0.81 倍、10.5px 标注实际仅 **8.4px**；
   390px 手机端更降到 **6.4px**。
   → ① `.capability` 单列断点从 900px **提到 1100px**（900–1100 两列窄格反而更糊）；
     ② 图上限 520px 居中、容器不足 460px 时横向滚动承接；
     ③ tech 页 960 宽幅图单独给 900px 下限（`is-wide`）。
   涉及 `.hero-figure` 同类坑：grid 子项 `min-width:auto` 被内部 SVG 顶到 494px，
   右溢 124px 被 `.hero` 的 `overflow:hidden` **静默裁掉** → 加 `.hero-split > * { min-width:0 }`。

### 6.3 顺带修掉一个会伤线上的缺陷：旧 CSS 被浏览器强缓存

排查中发现浏览器持续使用**缓存里的旧 style.css**（`location.reload(true)` 都不生效）。
这不是本地噪音 —— 同一个机制意味着**发布新版后访客会继续看到老版面**。

修法（`server.py`）：

- 页面 HTML 与 CSS 响应加 `Cache-Control: no-cache, must-revalidate`
  （不是"不缓存"，而是"用 ETag 回源确认"，未变时仍走 304，开销极小）；
- 引入 `SITE_VERSION`，用正则把 HTML 里 `assets/*.css` 引用统一重写为 `?v=N`
  （正则同时覆盖"还没版本号"和"版本号已过期"两种情况）；
- 字体等不可变二进制保持长缓存。

`/api/health`、`/api/meta` GET 200，`/api/identity` 为 POST-only（GET 405 属预期）；
路径穿越请求被正确拦为 404。

三类缓存策略实测生效：

| 资源 | `Cache-Control` | 理由 |
|---|---|---|
| HTML / CSS | `no-cache, must-revalidate` | 回源用 ETag 确认，未变仍 304；避免旧样式滞留 |
| 字体 / 图标 | `public, max-age=31536000, immutable` | 二进制不变，省掉条件请求 |

> ⚠️ 字体文件名里没有内容哈希，**换字体时要同步改名**，否则老访客会一直用缓存里的旧字体。

## 九、第 5 轮：交付前一致性核对

模型读不了图，所有排版结论都来自 DOM 断言的数值 —— 这带来一个风险：
**文档自述可能和实测悄悄漂开**。本轮把两份交付文档的每条数字回跑了一遍，揪出 4 处偏差：

| # | 文档原述 | 实测 | 处理 |
|---|---|---|---|
| 1 | 技术页 11 张 SVG、视口回归 9/9 | 8 个 `<svg>`（3 图 + 5 图标）、11 档全通过 | 表格改为「示意图（内容/图标）」分列，补暗色行 |
| 2 | 「字体等不可变二进制保持长缓存」 | 字体响应**没有** `Cache-Control`（`headers={}` 是空 dict） | 补 `_IMMUTABLE` 并注明改名要求 |
| 3 | 文档里那句"不含内部语境"的自我说明 | 该说明自身命中敏感词表 | 改为不含关键词的表述 |
| 4 | `/api/identity` 记作 200 | GET 405 / POST 200（设计为 POST-only） | 更正为「POST-only，GET 405 属预期」 |

> 教训：交付文档里的数字必须**一条命令就能验出来**。写"N 张图"而不写清是内容图还是含图标，
> 漂移是迟早的事。
