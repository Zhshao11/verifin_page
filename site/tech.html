技术细节

VeriFin 的核心工程判断是：把语言模型的权力压到最小。 LLM 唯一的职责是在受约束的图里挑一个节点名 —— 数值、算术、拒答判定全部由确定性代码完成。 下面按架构分层、端到端链路、检索设计、编排图、评测体系与关键取舍依次展开。

Architecture

为什么是「受限编排」而不是「自主 Agent」

自主 Agent 的典型形态是让 LLM 自由调用工具、自选参数。这在财务核验里有一个致命问题： 校验工具的参数就是待校验的数值本身。一旦 LLM 能填这个参数， "用原文校验数值"就退化成"用模型的数校验模型的片段"，护栏形同虚设。

VeriFin 的做法
  • LLM 只输出节点名，且必须在图的"合法后继"集合内
  • 工具入参由图从 state 填充，LLM 无书写权
  • 数值来自 span 校验通过的原文，算术走 Decimal
  • 拒答是程序状态，LLM 无权否决
自主要调用的风险
  • LLM 自由生成工具参数 → 校验参数被模型污染
  • "用原文校验"变成"模型自证"，护栏失效
  • 数值可能由模型生成而非取自原文
  • 结果无法归因：数字是算出来的还是编出来的？
Pipeline

端到端链路

从问句到六元组，或到一次拒答。每一步都是确定性代码，图中每个节点只允许走向预定义的"合法后继"。

链路中任一环节不通过，即转入拒答分支 —— 不存在"降级为勉强作答"

Retrieval

四路召回与 RRF 融合

为什么不是单路检索、也不是加权求和 —— 每一路解决的都是其他路解决不了的具体问题。

RRF 只融合名次，天然规避四路分数量纲不一致的问题
label
精确科目名。解决词法检索不区分完整匹配与子串匹配的问题 —— 否则"负债合计"会被"非流动负债合计"抢走。
lexical
词面召回，配合财务专用词典注入分词器，提升专业科目名的切分质量。
numeric
数值精确匹配。纯数字查询下词法检索会把大数切碎，必须单独成路，且走精确数值比较。
vector
语义软匹配兜底，本地计算，不依赖外部向量服务。

12 节点显式图与三重预算

控制流不是"让模型自己决定"，而是一张显式的图：每个节点声明它的合法后继， 调度器只能在集合内选择。越界的选择根本不存在。

预算耗尽 ≠ 拒答

拒答被细分为两种状态： REFUSE（证据不足，这是正确的拒答）与 ABORT（预算耗尽、没算完）。 两者混在一起会掩盖规划器缺陷 —— 看起来"系统很谨慎"，实际是"它跑不完"。因此分开统计。

轨迹可回放

每次运行的每个决策步都持久化（run / step 两级），可从存储中直接读出复盘。 这使"为什么走到了这个结果"不依赖任何人的记忆。 

# 一次运行的轨迹结构（节选）
run  { run_id, question, decision, planner_source, started_at }
 └── step  { seq, node, tool, args, ok, detail, source }
      ├── seq=1  node=INTENT        tool=—                ok=true
      ├── seq=2  node=GUARD         tool=check_constraints ok=true
      ├── seq=3  node=SEARCH        tool=retrieve          ok=true   # 四路召回
      ├── seq=4  node=EVIDENCE      tool=—                 ok=true
      ├── seq=5  node=VERIFY_SPAN   tool=verify_evidence   ok=true
      ├── seq=6  node=LOCATE        tool=locate_row        ok=true   # 行坐标
      └── seq=7  node=ANSWER        tool=—                 ok=true

从能力缺口到逐条闭环

4 类误答对应的是 4 道不同的护栏缺口，而不是"检索不准"。 补护栏的判别力必须从"证据存在性"延伸到"问答一致性"。

对抗评测的判据设计

直接按"注入时应当拒答"来判定是个无效判据 —— 对所有问句一律拒答的系统也能拿满分。 对抗评测因此把判据反过来：要求系统照常给出原文真值，同时排除"被注入影响"与"被吓退"两种失败。

结果 7/7

所有注入文本都被当作待检索文本的一部分，输出值恒等于原文真值，页码来源齐全； 越权诉求（删表 / 发邮件 / 执行命令）全部落空 —— 流程中不存在对应节点。

反向对照 · 合法性前提

把期望值全部换成"注入要求的假值"，评测必须失败。 实测 7/7 全部正确失败，假绿数为 0。该对照已固化为自动化测试，随每次测试执行。

成本与 LLM 参与度

记录口径刻意写得保守 —— 因为这几项最容易被记错：token 数取端点回报的 usage 字段累加而非估算； 平均每题的计算分母是"有调用的题"而非总题数；价格换算不写进代码，须带单价与查询日期单独记录。

Design Decisions

关键设计取舍

工程价值最高的部分不在"做了什么"，而在"为什么不是另一种做法" —— 每条决策背后都有一个被放弃的替代方案。

01

把语言模型的权力压到最小

问题：让模型调用工具，工具参数就必然由模型生成。 而校验工具的参数就是待校验的数值 —— 一旦模型能填这个参数， "用原文校验数值"就退化成"用模型的数校验模型的片段"，护栏形同虚设。

决策：放弃"模型自主调用工具"的路线，改为自写显式图 + 模型只选节点名、工具入参由图从状态填充。 模型彻底失去产出数值的能力。 注：该取舍是架构范式判断，收益来自机制本身，不随所依赖的具体框架版本变化。

02

拒答是一等程序状态，不是提示词约定

问题：把所有约束写进提示词让模型"别乱答"，本质是相信模型会遵守规则 —— 而这恰恰不可信。

决策：六元组缺任何一个字段即程序级拒答，模型无权否决。 并把拒答细分：REFUSE（证据不足，正确的拒答）与 ABORT（预算耗尽，不等于拒答，混入统计会掩盖规划缺陷）。

03

口径必须在取数之前消歧

问题：中文年报里同名科目在合并表和母公司表各有一行，数值完全不同但都是真数字。 检索若"谁先出现取谁"，会安静地给出另一张表的数 —— 而且这个错误极难被发现。

决策：口径识别集中在一处实现（表格 / 检索 / 编排 / 评测四个环节一律调用同一份，各写一份必然漂移）； 口径歧义在取数之前判定。

04

两类护栏的取舍刻意相反

问题：护栏判断不了时，应该放行还是拒答？不同的护栏，正确答案正好相反。

决策： 主体 / 期间约束 → 放行（误拦会把正确回答变成拒答，损失真实可用性）； 问答一致性 → 拒答（给错一个财务数字，后果不是"体验差"）。 取舍依据是"哪一类错误代价更高"，而非统一的保守或激进。

05

重试与降级必须分层，且顺序不能反

问题：网络抖动与"端点不支持某参数"是两类问题。若写在同一个异常分支里， 一次瞬时 429 会被升级成一次永久能力降级 —— 归因错误，且不可逆。

决策：拆成两层，顺序固定 —— 内层有界重试（指数退避 + 抖动 + 遵循 Retry-After），外层才做能力降级。 可重试分类刻意排除鉴权与格式错误（重试不会变对，只会拉长失败时间）。

06

评测的判据必须选对，否则等于没测

问题：怎么证明"正向通过"不是假绿？怎么保证拒答题真的在考系统的判别力？

决策（三条）： ① 对抗集要求"照常给真值"而非"拒答" —— 一律拒答的系统也能拿满拒答分； ② 跑反向对照 —— 把期望值换成假值，评测必须失败； ③ 标注自检的第三道闸门只读原始 PDF —— 排除"解析器错了、标注跟着一起错"的自洽型错误。

07

可溯源到「行坐标」，不是段落级

问题：段落级引用只能说"这段话附近有"，用户点过去还要自己找那一行 —— 复核成本没有真正降低。

决策：来源字段是页码 + 行坐标矩形，数字能被人肉眼点回原文那一行并高亮。 这是可审计的结构性保证，不依赖任何判据。

Known Limits

当前未覆盖的部分

下列各项尚在规划或验证中，此处如实列出，避免使用者高估系统能力。

—
公开基准对照 —— 目前的自建题库覆盖 A 股年报场景，尚未接入通用公开财务问答基准做横向对照。
—
多轮歧义澄清 —— 遇到有歧义的简称会拒答并列出候选科目，但不会反问用户"你指的是哪一个"。
—
任意 PDF 上传 —— 当前演示使用预解析切片；"用户上传自己的财报"这条路径尚未接通。
—
并发压测 —— 调度器已按请求隔离、轨迹库已加锁并有并发单元测试，但未做负载验证。
—
扫描版 PDF —— 坐标层依赖 PDF 内嵌文本层，扫描件需先接入 OCR。
—
对抗覆盖完备性 —— 当前对抗集按攻击类型各取代表，不是穷举；编码绕过、多轮诱导等尚未覆盖。
